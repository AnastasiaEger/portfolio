How I measured it

I built daily units and gross profit (price paid minus unit cost) for each category with a CTE, joined it to each promotion's date window, and compared the promo period with the 14 days before. This is the core query:

WITH daily AS (
  SELECT o.order_date, p.category,
         SUM(oi.quantity) AS units,
         SUM(oi.quantity * (oi.price_paid - p.unit_cost)) AS gross_profit
  FROM orders o
  JOIN order_items oi ON o.order_id = oi.order_id
  JOIN products p     ON oi.product_id = p.product_id
  GROUP BY o.order_date, p.category
)
SELECT pr.promo_name,
  AVG(CASE WHEN d.order_date BETWEEN pr.start_date AND pr.end_date
           THEN d.units END) AS units_per_day_promo,
  AVG(CASE WHEN d.order_date BETWEEN date(pr.start_date, '-14 days')
                                 AND date(pr.start_date, '-1 day')
           THEN d.units END) AS units_per_day_before
FROM promotions pr
JOIN daily d ON d.category = pr.category
GROUP BY pr.promo_id;

My recommendation

  • Repeat Bakery 15% off. It was the only promo that roughly broke even: units rose 34% while profit per day dipped just 2.5%.
  • Redesign Snacks BOGO. It doubled units but wiped out nearly all profit. Test 20% off instead, and measure whether most of the volume holds.
  • Stop or shrink deep, low-response discounts. Pantry 25% off cut profit by 38% for a 23% lift. Dairy 10% off barely moved demand (+14%).
  • Next test: smaller discounts on Produce, where demand responded strongly (+40%), to find the point where volume grows without giving away margin.

Limits and next steps

  • This is a before-and-after comparison, not an A/B test. Each promo is compared with the two weeks before it, so other changes in that time (seasonality, holidays, marketing) could also affect the results.
  • With real data, I would run an A/B test: offer the promotion to a random group of customers and compare them with a control group shopping at the same time.
  • I would also check who the promo reached: new customers it brought in, versus existing customers who would have bought anyway.
All data is made up for practice: 24 products, 6 promotions, 2,763 orders from Aug 3 to Oct 25, 2026. Built with SQL (SQLite). Figures compare each promotion with the 14 days before it in the same category, so they don't control for seasonality.
